我想做的不是 Live2D 表情生成器

发表于 2026-10-09
  • Aki's Memory
首页 AG99

真正有生命感的虚拟角色，不应该只是 “根据一句话换一个表情”，而应该有一个会被扰动、会恢复、会疲惫、会留下痕迹的内部系统。

最近准备验证一个 Live2D 相关的想法。

它现在还不是一个已经证明有效的方案，更像一个待实验的系统假设：

最初它很容易被理解成一个 “AI 表情生成器”：

用户说一句话，AI 判断情绪，然后让 Live2D 做出对应表情。

但我现在真正想验证的不是这个。

我更关心的是：

Live2D 的表情能不能不是被直接选择出来的，而是从一个持续运行的内部状态里自然读出来？

# 1. 旧范式：表情是输出

传统 Live2D 交互里，表情通常是一段被触发的输出：

这种方式稳定、直接，也足够做很多产品。但它的中心仍然是 “事件触发表现”：有事件就播放动作，没有事件就回到 idle。

哪怕是我正在写的 murphys7017/AG99live 也是一样的，不过是变成了大模型从给定的范围中选择 expression 的值。

我想验证的是另一种方向：

角色是否可以先有一个持续运行的内部系统，表情只是这个系统在某一刻的外显？

所以这次我不想继续只在 “让大模型选择哪个 expression” 上加复杂度。

更想做的是先扫描已有项目里的 motion、expression、参数映射和旧动作生成逻辑，把这些真实素材和约束整理出来，再让大模型基于这个项目现场生成下一版生命系统的候选方案。

也就是说：

这样生成出来的不是凭空想象的 “表情系统”，而是从真实模型和已有项目里继续长出来的东西。

# 2. 我想要的是：角色先活着，再表达

这个想法的方向不是：

而是：

用户输入不再是一个 “命令”，而是一种环境扰动。一句夸奖、一句调侃、一段沉默、一种语气，都不直接告诉角色 “你现在要笑”。

它们更像天气，进入角色所在的内部生态。

然后角色根据自己的能量、压力、信任、注意力、好奇和疲惫程度，产生不同的外显。

同样一句 “今天见到你很开心”，在不同状态下应该有不同反应：

  • 精力高、压力低：可能明显开心，眼睛亮起来，身体轻轻晃动。
  • 压力高、亲近感也高：可能有点害羞，想靠近但又躲闪。
  • 能量低：可能只是很轻地笑一下，动作幅度变小。
  • 长期信任高：反应更自然、更稳定，不会像第一次听到那样剧烈。

这个假设的关键是：

表情不是文本分类的结果，而是内部状态被扰动后的外显。

# 3. LLM 和文本向量的位置

这个系统里，大模型当然有用，但我不想让它直接操控角色。

也就是说，我不希望 LLM 直接决定：

  • 现在是什么表情
  • 播放哪个 motion
  • 嘴角是多少
  • 头歪多少度
  • 眼睛睁多大

如果让 LLM 直接控制这些东西，短期看很聪明，长期看可能会很散。

因为大模型擅长理解语义，却不天然擅长维护一个连续、稳定、可恢复的实时身体系统。

所以我现在设想的输入分成两层。

第一层是低维情绪扰动，用来描述这次输入在物理意义上 “推了系统一把”：

第一版可以是 6 个维度：

第二层是处理过的文本向量。

它不是拿来直接决定表情，而是用来决定扰动进入系统的空间位置、形状和响应区域。

也就是说：

这些输入都不会直接变成表情。

它们只是进入系统的一次扰动。

真正决定角色怎么表现的，是扰动进入之后，系统内部如何演化。

# 4. 从情绪标签到环境场

我现在越来越不想用 “开心、伤心、生气、害羞” 这种标签作为核心。

不是因为这些标签没用，而是因为它们太像结果了。

一个角色到底是不是 “害羞”，不应该只由输入决定，而应该由多个变量共同形成。

比如：

这才更像害羞。

所以我把外部输入先转成一个环境场：

这里需要分开看：

低维情绪扰动更适合沉淀成环境场。

处理过的文本向量则更适合决定扰动注入的位置、形状和响应区域。

环境场不是用户输入的复制品。

它更像输入被系统沉淀后的 “气候”。

一句话不会瞬间改写角色。

它会让环境变暖一点、变紧一点、变亮一点、变模糊一点，然后这个环境再慢慢影响角色内部状态。

这一步很重要。

因为它让系统有了惯性。

角色不再像按钮一样被点击，而是像一个处在气候里的生物。

# 5. 角色内部状态：表情背后的身体

环境场之外，还需要角色自己的内部状态。

我现在用的第一版内部状态大概是：

这些变量的意义不在于 “模拟人类心理学有多准确”。

它们更像一组工程上的控制变量。

它们回答的是：

  • 角色现在有没有力气表现？
  • 角色是否正在关注用户？
  • 角色是否信任这个互动对象？
  • 角色是否被压力压住？
  • 角色面对新奇东西是探索还是退缩？
  • 当前情绪能不能外显出来？

这样一来，Live2D 表情就不再是单纯的脸部参数。

它背后有一个 “身体”。

开心也会累。

紧张会让动作变小。

信任会缓冲压力。

好奇会提高注意力。

长期高刺激会消耗能量。

安全感会慢慢让系统恢复。

这些东西组合起来，角色才会开始有一点 “当下状态”。

然后 Live2D 参数会根据这个倾向被调制。

# 7. 真正的核心：反馈闭环

这个项目让我最兴奋的地方，是它最后可能不是一个 “AI 生成动作” 的问题，而是一个反馈系统问题。

我现在最想做的是几个闭环。

# 兴奋 - 疲劳 - 恢复

这会让角色不能无限兴奋。

它会开心，但开心也有成本。

# 压力 - 收缩 - 安全

这会让角色不是简单地 “生气” 或 “害怕”，而是出现收缩、犹豫、恢复这些过程。

# 亲近 - 信任 - 外显

这会让互动留下长期痕迹。

角色不是每次都从零开始认识你。

# 新奇 - 好奇 - 困惑

这会让 “困惑” 和 “好奇” 不再只是两个表情，而是同一类扰动在不同状态下的分化。

# 8. 下一步：生命场

在现在这个版本之后，我又开始想进一步抽象。

如果只用几个标量变量，系统虽然可控，但空间感还不够。

于是下一步我想做一个独立的 Life Field Kernel。

它可以先和 Live2D 解耦，只负责一件事：

想象一个 80 x 80 的二维生命场。

每个 cell 都有：

外部输入不再只是 “情绪数值”，而是变成两层：

文本 embedding 被压缩成一个语义向量。

场里的每个 cell 有自己的 semantic receptor。

输入向量和 cell receptor 做匹配，形成一个 injection mask。

然后扰动进入场，开始扩散、耗散、留下残留、恢复、再次激发。

这时，Live2D 不再直接读文本，也不直接读情绪标签。

它读的是生命场的宏观形态：

  • 激发中心在哪里
  • 压力是否聚集
  • 能量是否不足
  • 残留是否被重新唤醒
  • 波形是扩张还是收缩
  • 场是否稳定还是混乱

然后再把这些形态读成头部、眼睛、嘴角、身体、呼吸、表情扩展参数。

这个方向最吸引我的是：

语义不再直接控制表情，而是改变生命场的扰动形状；表情是生命场演化后的读出结果。

# 9. 准备验证什么

这件事现在还只是一个想法，下一步要做的是验证它是否真的成立。

我最想验证的不是 “AI 能不能识别情绪”，而是这些更底层的问题：

  • 低维情绪扰动加处理过的文本向量，是否足够驱动一个可观察的生命场。
  • 已有项目的扫描分析，是否能帮助大模型生成更贴合真实模型的扰动编码和 readout 映射。
  • 语义向量决定扰动形状，而不直接决定表情，这条链路是否可行。
  • 简单的激发、扩散、抑制、残留、恢复规则，能不能产生稳定但不死板的动态。
  • 从生命场读出的宏观指标，能不能稳定映射到 Live2D 的头部、眼睛、嘴角、身体和呼吸。
  • 同一句输入在不同内部状态下，是否真的会产生不同但可解释的外显。
  • 系统会不会很快发散、冻结、乱跳，或者变成另一种更复杂的 if-else。

如果这些问题有一部分能跑通，这个方向才算有继续深入的价值。

它吸引我的地方在于，它把 Live2D 表情生成从一个 “分类问题” 变成了一个 “生命系统问题”。

旧问题是：

这句话应该触发哪个表情？

新问题是：

一个持续运行的角色，被这句话扰动之后，会如何代谢、恢复、记住，并在身体上表现出来？

这两个问题完全不一样。

前者追求准确映射。

后者追求动态一致性。

前者像查表。

后者像养一个小生态。

如果这个假设能被验证，角色的表现就不只是 “AI 很会选表情”，而是：

  • 没有输入时也有轻微生命感。
  • 同一句话在不同状态下反应不同。
  • 长期互动会留下痕迹。
  • 情绪不会瞬间切换，而会过渡和恢复。
  • 表情、动作、呼吸、眼神来自同一个内部状态。
  • 系统可以被观察、调参和解释。

这可能才是虚拟角色真正有生命感的关键。

# 10. 一句话总结

我现在想做的不是一个 Live2D 表情生成器。

而是准备验证这样一个连续系统：

在这个系统里，AI 不是导演。

AI 更像感知器。

它负责理解外部世界发生了什么。

但角色怎么反应，不应该完全交给 AI 即兴发挥。

角色应该有自己的身体、惯性、能量、压力、恢复力和历史痕迹。

也就是说：

真正有生命感的 Live2D，不是 “更聪明地选择表情”，而是让表情从一个持续运行的内部世界里自然长出来。
